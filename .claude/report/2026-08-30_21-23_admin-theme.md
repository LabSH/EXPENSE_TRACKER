# 관리자 테마 전면 교체 — 라벤더/보라 → 번트 오렌지
> 작업일시: 2026-08-30 21:23

## 전제
사용자 화면(크림 + sage) 디자인은 **그대로 유지**하고 관리자 화면만 교체.
사용자 토큰(`--color-cream*`, `--color-sage*`)과 `.theme-cream` 블록은 미변경.

## 선정 근거
인디고(A) → 틸(T2) → **번트 오렌지** 순으로 반려·재선정. 최종은 사용자 선택.

**배경은 중성 쿨 슬레이트, 액센트만 웜 오렌지**로 두는 구조. 두 축이 모두 작동한다.
```
사용자   웜 크림 배경  +  sage 초록 (H156)
관리자   쿨 슬레이트   +  번트 오렌지 (H40)   ← 배경 온도 반대, 액센트 116° 이격
```
sage와의 이격 116°는 지금까지 후보 중 가장 넓다 (인디고 108° / 틸 54°).

### 알려진 트레이드오프 — 에러색 `blush`와 근접
`blush` `#D95F3B`(H37, 관리자 33회 사용)와 액센트 `#BB4B1F`(H40)는 **3° 이격, ΔE 7.7**.

ΔE 눈금 (OKLab 거리 ×100, JND≈2):
```
0.5   구분 불가          #D95F3B vs #DA613D
4.1   같은 계열 인접색    #D95F3B vs #C9542F
7.7   번트 액센트 vs blush        ← 현재
9.5   틸 vs sage
24.2  sage vs blush
34.9  구 violet vs blush          ← 이전 관리자 테마
```
혼동될 수준은 아니지만 **같은 웜 계열의 두 색조**로 읽힌다. 이전 보라(34.9)가 주던
"액션 vs 위험"의 즉각적 구분은 약해진다. 삭제 액션은 색만이 아니라 아이콘·라벨로도
구분되게 유지할 것.

**관리자 전용 에러색 분리는 검토했으나 채택하지 않음** — 크림슨(#CC454F) ΔE 6.4,
레드(#C94845) ΔE 4.8로 번트와 명도가 가까워져 오히려 더 나빠진다.

## 변경 내용

### 1) `input.css` — 관리자 토큰 10개
| 토큰 | 이전 | 이후 |
|---|---|---|
| `--color-admin` | `#F2F0FA` | `#EFF2F6` |
| `--color-admin-surface` | `#FDFCFF` | `#FBFCFE` |
| `--color-admin-subtle` | `#ECEAF5` | `#E8ECF0` |
| `--color-admin-border` | `#DDD9EE` | `#D7DDE4` |
| `--color-ink` | `#1E1B2E` | `#192532` |
| `--color-ink-soft` | `#58556B` | `#4E5863` |
| `--color-ink-muted` | `#757386` | `#6C757E` |
| `--color-violet` → **`--color-admin-accent`** | `#6246ea` | `#BB4B1F` |
| `--color-violet-light` → **`--color-admin-accent-light`** | `#f0eeff` | `#FFEFE8` |
| `--color-violet-mid` → **`--color-admin-accent-mid`** | `#b8aaee` | `#E7A58E` |

`ink` 계열은 `:root` 값이라 관리자 전용이다 — 사용자 화면은 `.theme-cream` 이 웜 값으로 덮어쓰므로 영향 없음.

### 2) 토큰 이름 변경 `violet` → `admin-accent` (103건)
값이 인디고인데 이름이 `violet`이면 함정이 되므로 개명. `admin-*` 계열과 이름이 맞아 테마 개념도 일관됨.
Tailwind 기본 팔레트(`violet-300`, `bg-violet-50`, `text-violet-600`)는 정규식 lookahead로 제외.

### 3) 공통 드롭다운 fragment 테마 분리 — **선행 필수 작업**
`fragments/dropdown.html` 이 `bg-admin-surface` / `border-admin-border` / `hover:bg-admin-subtle` 를
하드코딩한 채 **사용자 고정지출 화면에서 5회 렌더**되고 있었음. 그대로 두면 관리자 토큰 변경이
사용자 화면 드롭다운으로 새어나감.

기존 `theme` 파라미터에 `ctrlBorder`, `ctrlHover`, `panelBg` 를 추가해 분리. 이제 색상 하드코딩 0건.

### 4) 하드코딩 색상 정리
- `input.css` 의 `.form-select` — 5개 하드코딩 hex를 `var(--color-*)` 로 교체.
  chevron SVG의 stroke가 구 `ink-soft`(`#6E6A85`)로 남아 있던 것도 현재 값으로 갱신.
- 관리자 4개 페이지의 `::-webkit-scrollbar-thumb` `#DDD9EE` → `#D1DEEB`
- `admin/users.js` 의 `AVATARS` 첫 색상 `#6246ea` → `#486CBB`

### 5) 사용자 사이드바의 관리자 진입 링크 (`fragments/sidebar.html:96`)
Tailwind 기본 팔레트를 쓰고 있어 토큰 변경이 반영되지 않던 곳.
`hover:border-violet-300 hover:bg-violet-50 hover:text-violet-600`
→ `hover:border-admin-accent-mid hover:bg-admin-accent-light hover:text-admin-accent`

## 대비 검증 (surface `#FBFCFE` 기준)
```
ink          #192532  15.13  통과
ink-soft     #4E5863   7.05  통과
ink-muted    #6C757E   4.56  통과
admin-accent #BB4B1F   4.94  통과
```
액센트 전 배경: surface 4.94 / accent-light 4.53 / page bg 4.52 / 흰 글자 5.07.
흰 글자가 그대로 통하므로 `bg-admin-accent text-white` 패턴 23곳은 수정 불필요.

텍스트 램프는 배경 색조가 바뀔 때마다 함께 재계산했다 — 배경만 바꾸고 ink를 두면
배경과 글자의 색조가 어긋난다.

**유일한 미달 조합은 `text-admin-accent` on `bg-admin-subtle`(4.27)** 이나
템플릿 전체 사용 0건이라 실사용 문제 없음.

## 미해결 (의도적으로 제외)
`blush`(3.64), `sky`(4.26)는 여전히 AA 미달. 두 토큰은 **사용자·관리자가 공유**하므로
값을 바꾸면 "사용자 디자인 유지" 전제를 깬다. 별도 작업으로 분리 필요.
관리자에서 blush 33회, sky 7회 사용 중.

## 잠재적 함정
`calendar.js` 의 기본 테마가 여전히 `admin`. 새 사용자 페이지에서
`CalendarPicker.init(['x'])` 처럼 테마 인자를 빠뜨리면 관리자 색이 딸려온다.
현재는 고정지출만 캘린더를 쓰며 `'cream'` 을 명시하고 있어 문제없음.
