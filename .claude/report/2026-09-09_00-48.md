## 완료된 작업

### 1. 고정지출 add/edit/delete 시 데이터 소실 버그 수정

**원인**
- `submitFixedExpense()` / `deleteFixedExpense()` 가 성공 후 `htmx.ajax('GET', '/fixed-expense', '#main-content')` 로 프래그먼트를 통째로 리로드.
- htmx 1.9.12 는 `useTemplateFragments:false`(기본)라 swap 마다 프래그먼트 내 인라인 `<script>` 를 전역 스코프에서 재실행.
- 이번 개발분에서 스크립트 최상위에 처음으로 `const FE_CYCLE_MONTHS = {...}` 가 추가됨 → 2번째 실행 시 `SyntaxError: Identifier 'FE_CYCLE_MONTHS' has already been declared` 로 블록 전체가 죽고, 새로 swap 된 빈 DOM에 `renderFixedExpenses()` 등이 실행되지 않아 목록·요약·다가오는 지출이 전부 빈 상태가 됨.
- 같은 원인으로 "고정지출 → 다른 메뉴 → 고정지출" 네비게이션 왕복 시에도 동일 증상.

**조치 (A안: 프래그먼트 리로드 제거 + IIFE 캡슐화)**
- 백엔드: `GET /fixed-expense/upcoming` 엔드포인트 추가 (`FixedExpenseController`). 우측 패널(요약 + 다가오는 지출)을 JSON 반환. `FixedExpenseFacade.findUpcoming` 재사용.
- 프론트: `refreshFixedExpenses()` 헬퍼 추가 — `/fixed-expense/data`(현재 필터 유지) + `/fixed-expense/upcoming` 을 `Promise.all` 로 받아 `renderFixedExpenses` / `renderFeSummary` / `renderFeUpcoming` 재호출.
- `submitFixedExpense()` / `deleteFixedExpense()` 의 `htmx.ajax(...)` → `await refreshFixedExpenses()` 로 교체.
- 프래그먼트의 두 번째 `<script>` 블록 전체를 `(function(){ 'use strict'; ... }())` IIFE 로 래핑 → swap 마다 재실행돼도 최상위 `const` 재선언 에러가 사라지고 전역 오염 없음.
- 인라인 `onclick` 이 참조하는 핸들러 5개만 `window.` 로 명시 노출: `openFixedExpenseViewModal`, `openEditFixedExpenseModal`, `openDeleteFixedExpenseModal`, `removeFeFile`, `closeFixedExpenseViewModal`.

### 2. 자동이체 체크박스 재디자인

- 기존: 네이티브 체크박스 + `accent-sage` (폼의 다른 cream 테마 컨트롤과 이질적).
- 사용자와 여러 차례 반복하며 조정:
  - 웜(cream/sage) 테마 토큰으로 매핑, `sr-only` + `peer`/`has-[]` 패턴 (Tailwind v4).
  - `peer-checked:` 는 형제만 잡으므로, span 안에 중첩된 체크마크 SVG 는 `group-has-[:checked]:` 로 표시 (SVG 가 안 보이던 버그 수정).
  - 최종안: 카드형(테두리 pill) + 옆 계좌 드롭다운 버튼과 동일한 박스 모델(`px-3.5 py-1.5 border`, `leading-5`)로 높이 34px 일치. 글자는 다른 폼 라벨과 같은 `text-xs font-medium text-ink-soft` + `peer-checked:text-ink`.
  - 빈 라벨 줄(`<span aria-hidden>&nbsp;</span>`)로 옆 필드와 세로 정렬 (`grid items-end`).
  - 제외: `:disabled` / `:indeterminate` 상태(이 화면에서 미사용), 쿨/플랫 테마 토큰.
- `output.css` 재빌드.

### 3. 공통 모달 열기/닫기 애니메이션 헬퍼 신설 (전역)

- 문제: 열 때만 `anim-slideUp`(아래→위 + 페이드인) 재생, 닫을 때는 `classList.add('hidden')` 로 즉시 사라져 비대칭.
- 신규 `src/main/resources/static/js/common/modal.js` — `toast.js`/`loading.js` 와 동일한 IIFE + `window.Modal` 패턴.
  - `Modal.open(idOrEl)`: `hidden` 제거 + 안쪽 `.anim-slideUp` 박스를 remove→reflow→add 로 재생 강제 (기존 admin 3파일의 reflow 트릭 흡수).
  - `Modal.close(idOrEl)`: 바깥 컨테이너에 `pointer-events:none` + `anim-modalFadeOut`, 안쪽 박스 `anim-slideUp`→`anim-modalOut` 교체, `animationend`(자식 이벤트 필터) 또는 fallback `setTimeout(230ms)` 로 `hidden` 처리 + 클래스 원복. 이미 닫혔거나 닫히는 중이면 no-op. 닫는 도중 재오픈 시 지연된 finish 취소.
- `input.css` 에 닫기 키프레임 추가: `@keyframes modalOut`(살짝 내려가며 사라짐) / `@keyframes modalFadeOut`(백드롭 페이드아웃) + `.anim-modalOut` / `.anim-modalFadeOut` (.18s ease-in). 중복 `@keyframes slideUp` 는 손대지 않음.
- `config/config.html` 에 `<script th:src="@{/js/common/modal.js}">` 추가 (전 페이지 `<head>` 로드).
- 마이그레이션: 고정지출 3개 모달, 설정 2개(계좌 추가·수정 / 삭제 확인), 대시보드 1개(내역 추가), 관리자 코드·사용자 다수 + 로그 1개의 열기/닫기 호출을 `Modal.open`/`Modal.close` 로 위임. admin 3파일의 reflow 트릭 제거.
- 모달 아닌 `hidden` 토글(대시보드 tweaks-panel·금액 미리보기·결제수단 드롭다운 등)은 미변경.
